# Subtask 09: Define a GTM Folder Organization Strategy

## Objective

Use GTM folders consistently so people can find and review related tags, triggers, and variables without mistaking folders for runtime isolation or access control.

## Scope

- Folder taxonomy, naming, ownership, and lifecycle.
- Placement of scoped tags, triggers, and user-defined variables.
- Handling shared components and temporary project folders.

## Work Items

1. Inventory current folders and unfiled items in scope.
2. Choose one primary grouping principle and define exceptions.
3. Define naming, shared-item, temporary-folder, and cleanup rules.
4. Refile the POC components and verify dependencies remain intact.

## Deliverables / Outputs

- Folder taxonomy and naming guideline.
- Before/after scoped folder inventory.
- Cleanup checklist and named owner.

## Expected Result

Related GTM components are easy to discover, folder sprawl is controlled, and users understand that folders do not affect firing, permissions, or publication.

## Acceptance Criteria

- [ ] A primary folder grouping principle and naming standard are documented.
- [ ] Every POC tag, trigger, and user-defined variable has a deliberate folder placement.
- [ ] Shared dependencies and unfiled items have explicit rules.
- [ ] Temporary folders have an owner and cleanup date.
- [ ] Preview tests confirm that reorganization did not change behavior.

## Dependencies

- Scoped tag, trigger, and variable inventories.
- GTM workspace access.

## Estimated Effort

**3 hours** — inventory 0.5h, taxonomy 1h, organization/test 1h, review 0.5h.

## Answers

### 1. What is semantic HTML, and why does it matter?

Semantic HTML uses elements according to their meaning, such as `nav`, `main`, `article`, `button`, and `form`, instead of using generic containers for everything. It gives browsers and assistive technologies useful structure, supplies built-in keyboard behavior, improves maintainability, and can help search engines understand a page. Use ARIA only when native HTML cannot express the required semantics.

### 2. What is the difference between `div`, `section`, and `article`?

- `div` is a generic container with no semantic meaning.
- `section` groups a thematic part of a document and normally has a heading.
- `article` is a self-contained composition that could stand alone or be reused, such as a post, comment, or product card.

Do not choose an element based on its default appearance; CSS can change appearance.

### 3. How should a page's heading hierarchy be structured?

Use headings to describe document structure, not to obtain a font size. Start with the page's main heading and nest subsections logically without skipping levels where possible. A page can technically contain multiple `h1` elements, but one clear page-level `h1` is usually easiest for users and tooling to understand.

### 4. What is the difference between `strong`/`em` and `b`/`i`?

`strong` expresses strong importance and `em` expresses stress emphasis. `b` draws attention without adding importance, while `i` marks text in an alternate voice or mood, technical terms, or idioms. Their default styles may look alike, but their semantics differ.

### 5. What does the HTML `lang` attribute do?

`<html lang="en">` declares the document's language. Screen readers use it for pronunciation, browsers use it for features such as spell-checking and hyphenation, and search or translation tools use it to interpret content. Apply another `lang` value to a passage when its language changes.

### 6. How do you write useful image alternative text?

Describe the image's purpose in its context, concisely. Use `alt=""` for a purely decorative image so assistive technology can ignore it. Do not repeat nearby text or begin with “image of.” If an image contains essential complex information, provide a short `alt` plus a fuller text explanation nearby.

### 7. Why use a `button` instead of a clickable `div`?

A native `button` is focusable, keyboard-operable, exposed with the correct accessibility role, and supports disabled and form behavior. A clickable `div` has none of this automatically and requires error-prone JavaScript and ARIA to imitate it. This is the principle “use the native element first.”

### 8. When should you use a link versus a button?

Use an anchor with `href` for navigation to a URL or document location. Use a `button` for an action, such as submitting, opening, toggling, or deleting. This distinction provides the expected semantics and keyboard/browser behaviors, including opening links in a new tab or copying their address.

### 9. How do you associate a label with a form control?

Use an explicit association:

```html
<label for="email">Email</label> <input id="email" name="email" type="email" />
```

Alternatively, wrap the control inside `label`. A placeholder is not a label: it disappears, may have low contrast, and does not reliably provide the same accessible name.

### 10. What is the difference between `disabled`, `readonly`, and `aria-disabled`?

- `disabled` prevents interaction, removes most controls from sequential focus, and excludes their values from form submission.
- `readonly` keeps supported text controls focusable and submitted but prevents value editing.
- `aria-disabled="true"` only communicates an inaccessible state; code must still prevent the action and decide how it behaves in the tab order.

### 11. What is native HTML form validation?

The Constraint Validation API lets attributes such as `required`, `min`, `max`, `pattern`, and semantic input types define validity. Browsers block invalid submissions and expose states such as `:valid` and `:invalid`. Server-side validation remains mandatory because client-side validation can be bypassed; custom messages must also be accessible.

### 12. What do `autocomplete` and `inputmode` do?

`autocomplete` tells the browser what real-world value a field expects, such as `email`, `current-password`, or `one-time-code`, enabling appropriate autofill. `inputmode` hints which virtual keyboard to show, such as `numeric` or `decimal`; it does not validate the value or change the input's data type.

### 13. How do you make an HTML data table accessible?

Use `table` only for tabular relationships, provide a meaningful `caption`, use `th` for headers, and add `scope="col"` or `scope="row"` for straightforward tables. Preserve a logical reading order. Complex tables may need explicit header associations, but simplifying the table is often better.

### 14. What are `data-*` attributes?

They store application-specific data on HTML elements without inventing non-standard attributes:

```html
<li data-user-id="42">Ada</li>
```

JavaScript can read it with `element.dataset.userId`, and CSS can select it with an attribute selector. Do not put sensitive data in HTML or use `data-*` as a substitute for meaningful semantics.

### 15. What is the difference between `async` and `defer` on scripts?

Both download classic external scripts without blocking HTML parsing. `async` executes as soon as downloaded, with no guaranteed order, so it suits independent scripts. `defer` executes after parsing and preserves document order, before `DOMContentLoaded`. Module scripts are deferred by default; `async` changes their scheduling too.

### 16. What are `srcset`, `sizes`, and `picture` used for?

`srcset` supplies image candidates, and `sizes` tells the browser the expected rendered width so it can choose an appropriate resource. `picture` with `source` enables art direction or format selection. These features reduce unnecessary bytes while letting the browser account for viewport size and pixel density.

```html
<img
  src="photo-800.jpg"
  srcset="photo-480.jpg 480w, photo-800.jpg 800w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="Team collaborating"
/>
```

### 17. Why specify `width` and `height` on images?

The attributes give the browser an intrinsic aspect ratio before the file loads, so it can reserve space and reduce Cumulative Layout Shift. CSS can still make the image responsive:

```css
img {
  max-inline-size: 100%;
  block-size: auto;
}
```

### 18. What do `loading="lazy"` and `decoding="async"` do?

`loading="lazy"` allows off-screen images or iframes to load near the time they are needed. Do not lazy-load a likely Largest Contentful Paint image because it may delay it. `decoding="async"` is a hint that image decoding need not block other rendering; neither attribute is a guarantee.

### 19. How does the native `dialog` element work?

`dialog.showModal()` opens a modal in the top layer, makes the rest of the document inert, and provides expected focus and Escape-key behavior. `dialog.show()` opens it non-modally; `close()` closes it. Use a visible close control, an accessible name, and `::backdrop` for the modal backdrop. Avoid merely toggling the `open` attribute for modal behavior.

### 20. What is the Popover API?

The Popover API creates non-modal top-layer UI such as menus and teaching tips, declaratively or with JavaScript:

```html
<button popovertarget="menu">Menu</button>
<div id="menu" popover>...</div>
```

An automatic popover supports light dismissal and Escape. Use `dialog.showModal()` when the rest of the page must become non-interactive.

### 21. What does the `inert` attribute do?

`inert` makes an element subtree non-interactive: its controls cannot receive focus or clicks, and its content is generally hidden from the accessibility tree. It is useful while an off-canvas region is unavailable. Unlike `aria-hidden`, it also suppresses interaction; do not place the current focus inside an inert subtree.

### 22. What is progressive enhancement?

Start with functional, semantic HTML; add CSS for presentation; then add JavaScript and newer features for enhanced behavior. Users still get the core content or task when a script fails, a feature is unsupported, or assistive technology is used. Feature queries such as `@supports` can apply CSS enhancements safely.

### 23. What is the CSS box model?

Every rendered box consists, from inside out, of content, padding, border, and margin. The first three contribute to the visible box; margin creates external space. `box-sizing` determines whether declared `width` and `height` describe only the content box or include padding and border.

### 24. What is the difference between `content-box` and `border-box`?

With the default `content-box`, declared width covers only content, so padding and borders increase the outer size. With `border-box`, declared width includes content, padding, and border. Margins are excluded in both cases. A common predictable reset is:

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

### 25. How do specificity and the cascade choose a winning declaration?

The cascade considers, broadly: relevance, origin and importance, cascade layer, specificity, scope proximity, then source order. Specificity compares ID, class/attribute/pseudo-class, and type/pseudo-element columns; it is not a decimal number. `!important` changes cascade precedence and should be a deliberate exception, not a specificity workaround.

### 26. What are cascade layers?

`@layer` establishes an explicit precedence order among groups of normal author styles, reducing specificity battles:

```css
@layer reset, base, components, utilities;
```

For normal declarations, later layers win over earlier layers regardless of selector specificity. Unlayered normal author styles outrank layered normal styles. Important declarations reverse layer order.

### 27. What is the difference between inheritance, `initial`, `inherit`, `unset`, and `revert`?

Some properties inherit their parent's computed value by default, such as `color`; many layout properties do not. `initial` uses the property's specification-defined initial value, `inherit` forces inheritance, `unset` means inherit for inherited properties and initial otherwise, and `revert` rolls back to a lower cascade origin (or earlier contextual default).

### 28. How do CSS custom properties differ from preprocessor variables?

Custom properties participate in the cascade, inherit, remain in the browser, and can change at runtime or by media/container query. Preprocessor variables are replaced at build time and have no cascade or runtime value. Use `var()` with an optional fallback:

```css
.card {
  color: var(--card-color, CanvasText);
}
```

### 29. What is the difference between pseudo-classes and pseudo-elements?

A pseudo-class selects an existing element in a state or relationship, such as `:hover`, `:focus-visible`, or `:nth-child()`. A pseudo-element targets an abstract part or generated box, such as `::before`, `::marker`, or `::first-line`. Modern syntax uses one colon for pseudo-classes and two for pseudo-elements.

### 30. What do `:is()`, `:where()`, and `:has()` do?

`:is()` groups selector alternatives and takes the specificity of its most specific argument. `:where()` groups alternatives but always has zero specificity. `:has()` is a relational pseudo-class that can select an element based on matching relatives—for example, `.field:has(input:invalid)`. Use it thoughtfully because broad relational matching can cost more than simple selectors.

### 31. How does native CSS nesting work?

Nesting groups related rules without a preprocessor. `&` represents the parent selector and is required where the nested selector would otherwise be ambiguous:

```css
.card {
  padding: 1rem;
  &:hover {
    box-shadow: 0 0.25rem 1rem #0002;
  }
  & > h2 {
    margin-block-start: 0;
  }
}
```

Avoid deep nesting because it couples markup and increases selector complexity.

### 32. What creates a stacking context?

A stacking context is an independent z-axis group. Common creators include the root element, positioned elements with a non-auto `z-index`, fixed/sticky elements, `opacity` below `1`, transforms, filters, isolation, containment, and top-layer elements. A huge child `z-index` cannot escape its parent's stacking context, which explains many “z-index does not work” bugs.

### 33. How do the CSS `position` values differ?

- `static`: normal layout; offsets and `z-index` generally do not apply.
- `relative`: stays in normal flow but can be visually offset and becomes a containing block.
- `absolute`: removed from normal flow and positioned against its containing block.
- `fixed`: positioned relative to the viewport in typical cases.
- `sticky`: acts relative until a scroll threshold such as `inset-block-start: 0`, then sticks within its scroll container.

### 34. When should you use Flexbox versus Grid?

Flexbox is primarily one-dimensional: it distributes and aligns items along a row or column, making it good for navigation, toolbars, and component internals. Grid controls rows and columns together, making it good for page or card layouts. They complement each other, and content requirements—not a blanket rule—should drive the choice.

### 35. What do `flex-basis`, `flex-grow`, and `flex-shrink` mean?

`flex-basis` is an item's initial main-axis size before free space is distributed. `flex-grow` is its share of positive free space, and `flex-shrink` controls contraction when space is insufficient. A common gotcha is the default `min-width: auto`; use `min-inline-size: 0` when a flex child must shrink below its content's intrinsic width.

### 36. What is CSS Grid's `subgrid`?

`subgrid` lets a nested grid reuse its parent's track sizing rather than defining independent tracks. This aligns internal content across sibling cards or sections:

```css
.card {
  display: grid;
  grid-template-rows: subgrid;
  grid-row: span 3;
}
```

The parent must be a grid, and the child must span tracks on the axis using `subgrid`.

### 37. What is the difference between `auto-fill` and `auto-fit`?

Both repeat as many grid tracks as fit. `auto-fill` retains empty implicit tracks, while `auto-fit` collapses empty tracks so existing items can stretch. A common responsive layout is `repeat(auto-fit, minmax(min(100%, 16rem), 1fr))`.

### 38. What is margin collapsing?

Adjacent vertical margins of block boxes in normal flow can combine into one margin—usually the largest positive margin rather than their sum. Parent and first/last child margins can also collapse under certain conditions. Flex and grid item margins do not collapse. Prefer `gap` for consistent spacing inside flex or grid layouts.

### 39. What is a block formatting context?

A block formatting context (BFC) is an independent region for block layout. It contains internal floats and prevents external floats from intruding. `display: flow-root` deliberately creates one without unrelated side effects; floats, absolutely positioned elements, and certain `overflow`, flex, grid, or containment values also create BFCs.

### 40. What is the difference between `px`, `em`, and `rem`?

`px` is a CSS reference pixel, not necessarily one physical screen pixel. For `font-size`, `em` is relative to the parent's computed font size; for most other properties, it is relative to the element's own font size. `rem` is relative to the root element's font size. Relative units help layouts respond to user font preferences; avoid disabling zoom.

### 41. What are modern viewport units?

`vw` and `vh` use the default viewport size. On mobile, browser UI can make height ambiguous, so CSS adds small (`svh`), large (`lvh`), and dynamic (`dvh`) viewport units. `100dvh` follows the currently visible viewport; `100svh` provides a stable size that avoids being covered when browser controls are present.

### 42. What are CSS logical properties?

Logical properties describe flow-relative directions rather than physical left/right/top/bottom. Examples include `margin-inline`, `padding-block`, `inline-size`, and `border-inline-start`. They adapt naturally to right-to-left languages and vertical writing modes, reducing direction-specific overrides.

### 43. What is the difference between media queries and container queries?

Media queries respond to viewport or device/media features. Container queries respond to a containing element, so a reusable component can adapt to the space it actually receives:

```css
.wrapper {
  container-type: inline-size;
}
@container (width > 40rem) {
  .card {
    grid-template-columns: 1fr 2fr;
  }
}
```

Use media queries for page-level conditions and container queries for component-level responsiveness.

### 44. How do `min()`, `max()`, and `clamp()` help responsive design?

They choose values dynamically without multiple breakpoints. `min()` selects the smallest expression, `max()` the largest, and `clamp(min, preferred, max)` constrains a fluid preferred value:

```css
h1 {
  font-size: clamp(2rem, 1rem + 4vw, 5rem);
}
main {
  inline-size: min(100% - 2rem, 70rem);
}
```

### 45. How do you truncate text with CSS?

For one line:

```css
.one-line {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

For multiple lines, use `line-clamp` where supported, commonly with the established prefixed pattern:

```css
.three-lines {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 3;
  overflow: hidden;
}
```

Truncation hides information visually, so ensure essential content remains available.

### 46. How do you create gradient text accessibly?

Clip a background gradient to the text and retain a solid `color` fallback. Avoid making text transparent outside a feature query:

```css
.gradient-text {
  color: #7c2d92;
}

@supports (background-clip: text) {
  .gradient-text {
    background: linear-gradient(90deg, #b42318, #175cd3);
    background-clip: text;
    color: transparent;
  }
}
```

Check contrast across the entire gradient and in forced-colors mode.

### 47. How should focus indicators be styled?

Never remove focus outlines without an equally visible replacement. `:focus-visible` lets browsers show a strong indicator mainly when keyboard-like interaction needs it. Use sufficient contrast and an outline that is not clipped:

```css
:focus-visible {
  outline: 3px solid #0b57d0;
  outline-offset: 3px;
}
```

DOM order should also match the visual and keyboard order.

### 48. How do you respect reduced-motion preferences?

Use the user's `prefers-reduced-motion` setting to remove or reduce non-essential motion, especially large movement, parallax, and continuous animation:

```css
@media (prefers-reduced-motion: reduce) {
  .animated {
    animation: none;
    transition-duration: 0.01ms;
  }
}
```

Do not remove meaningful state feedback; replace motion with an immediate or gentler cue.

### 49. What is CSS containment, and what is `content-visibility`?

Containment lets an element isolate aspects of layout, paint, size, or style so the browser can limit work and components have fewer external effects. `content-visibility: auto` can skip rendering off-screen contents until needed. Pair it carefully with `contain-intrinsic-size` to reserve an estimated size and avoid scrollbar jumps or layout shifts.

### 50. How can HTML and CSS improve Core Web Vitals?

- **LCP:** prioritize the hero resource, serve responsive images, avoid lazy-loading the LCP image, and keep render-blocking CSS small.
- **INP:** keep interactions simple, avoid expensive style/layout recalculation, and break up long JavaScript work.
- **CLS:** provide image/media dimensions, reserve space for dynamic content, preload fonts selectively, and avoid inserting content above existing content.

Measure real users as well as lab tests; performance is an outcome, not a single technique.

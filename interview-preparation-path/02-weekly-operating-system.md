# Weekly Operating System

The default schedule is 14 hours. It favors active practice while keeping
weeknights short enough to sustain alongside a full-time job.

| Day | Time | Session |
| --- | ---: | --- |
| Monday | 1.5 h | Learn the week's mental model; make retrieval questions |
| Tuesday | 2 h | Focused implementation or coding drills |
| Wednesday | 1.5 h | Continue implementation; add tests and edge cases |
| Thursday | 2 h | System-design or technical explanation practice |
| Friday | 1 h | Closed-book recall, error-log review, light catch-up |
| Saturday | 3.5 h | Capstone deep-work block and written decision record |
| Sunday | 2 h | Timed mock or problem set |
| Sunday | 0.5 h | Score the week and schedule the next one |

This yields roughly 5.5 hours of study/review and 8.5 hours of active
application, close to the intended 40/60 split.

## Session template

For a 90–120 minute weekday session:

1. **Recall (10 minutes):** answer yesterday's prompts without notes.
2. **Main work (60–85 minutes):** one defined problem or implementation.
3. **Explain (10 minutes):** summarize aloud as if answering an interviewer.
4. **Log (10 minutes):** record mistakes, evidence produced, and the next action.

## Minimum viable week

When work or health reduces capacity, do 7 hours:

- one 90-minute concept block;
- two 60-minute coding blocks;
- one 3-hour capstone block;
- one 30-minute weekly review.

Keep the week's deliverable; reduce note-taking and optional reading. Do not
"repay" missed hours by exhausting the next week.

## Learning rules

- Start closed-book. Look things up only after forming a concrete hypothesis.
- Convert every topic into code, a diagram, an ADR, a measurement, or a recorded
  explanation.
- Revisit errors after 1 day, 1 week, and 3 weeks.
- Time-box research. If a topic does not change a design or implementation
  decision, capture a follow-up and move on.
- Treat sleep and one flexible evening as part of the plan, not as failure.
